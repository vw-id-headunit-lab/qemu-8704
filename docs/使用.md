# 使用

## 环境

Windows x64、Python 3.14。启动三系统时准备至少 8 GiB 可用提交内存和容纳私有固件及写层的磁盘空间。

```powershell
./MEB-EMU.ps1 setup
./MEB-EMU.ps1 doctor
```

`setup` 只在本项目创建 Python 环境和依赖目录。原生 DLL 和 qemu-img 来自锁定的 MSYS2 包，安装前核对归档和选定文件的 SHA256。

## 私有输入

使用经过离线准备的固件输入包。输入包包含 `manifest.json` 和其中明确列出的文件；条目格式见 `config/input-bundle.example.json`。把示例摘要替换为真实文件 SHA256，不放入个人账号、实车诊断备份或会话 RAM。

```powershell
./MEB-EMU.ps1 import -Bundle E:/my-firmware-inputs
```

导入器只复制清单内、摘要匹配的文件至 `var/inputs/`，不执行输入包中的程序，不覆盖已有不同内容。

采用预先生成的 ext4 数据种子；从零创建 ext4 的可选开发流程另外需要本机的 mke2fs，放在 `.local/deps/bin/mke2fs.exe`。

引导输入主要包括：原始内核／ramdisk／DTB／vLM／HCB，原包提取清单，原始存储布局与 backing，内核符号数据，HMI 安装介质，以及启动配置引用的私有准备结果。图形转发所需的 JNI、字体和 Java 派生文件由使用者从自己的原包生成，存放于 `var/inputs/derived/hmi/`；生成工具在 `src/emu/gl-forward/`。

## 启动

将 `config/launch.example.json` 复制为 `var/profile.json`，对照自己的输入调整相对路径，然后执行：

```powershell
./MEB-EMU.ps1 plan -Profile var/profile.json
./MEB-EMU.ps1 start -Profile var/profile.json
```

管理端点仅监听本机回环地址。原生窗口显示原厂源像素，左上角 FPS 只统计实际变化的已呈现画面。页面和指令台使用本次会话的随机访问 token。

## 打包

```powershell
./MEB-EMU.ps1 verify
./MEB-EMU.ps1 package
```

产物为 `dist/MEB-EMU-0.1.0-preview.1.zip` 及同名 SHA256 文件。打包器使用公开目录白名单，不从整个工作目录直接压缩。
