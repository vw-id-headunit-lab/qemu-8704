# qemu-8704 首次运行验证

验证环境：Apple Silicon macOS，同一宿主上的全新 Git 工作副本和独立运行目录。使用已安装的宿主依赖及使用者自备的 8704 输入；**不是全新机器无依赖测试，也不是原始更新包自动提取测试**。

实际结果：

- 初始化已按新目录重建配置和模块来源路径，不再依赖开发者的原目录；缺少输入、模块校验失败或目录已有会话时拒绝继续。
- `./MEB-EMU.sh test`：26 项测试全部通过（含路径初始化及源码缓存校验测试）。
- `./MEB-EMU.sh doctor`：退出 0。
- `./MEB-EMU.sh smoke`：退出 0，观测到 `prelaunch → running → paused → quit`，3 项镜像工具检查通过；此项不启动原厂固件。
- 独立副本冷启动成功；Linux UID65534 与 Android UID2000 分别返回 `QEMU_8704_CLEAN_LINUX_OK`、`QEMU_8704_CLEAN_ANDROID_OK`，两条命令均退出 0。
- 删除副本中的 QEMU 上游源码归档、Mesa 解包目录和下载缓存后，再次实际冷启动；两域分别返回 `QEMU_8704_CACHELESS_LINUX_OK`、`QEMU_8704_CACHELESS_ANDROID_OK`，均退出 0。这些缓存并非预编译载体运行必需，仓库不再依赖 Git LFS；重建 QEMU 才按官方来源和固定 SHA256 获取源码。
- 显式开启客体内模拟驻车电源后，原 HMI 显示中文顶栏、空调底栏和“请稍候…”页面。触控 down/up 实际返回 HTTP200，但不能将这一点表述为业务页面已可用；此副本完整加载和菜单交互仍未验收。
- Android 的指令通道通过不等于完整 framework 启动；QNX、IC/HUD、长期稳定性和持续动态帧率也未在本次验证中通过。

隐私排除规则对相同输入路径的检查为：BASELINE 未忽略（退出 1），MODIFIED 已忽略（退出 0），独立副本 ROLLBACK 恢复未忽略（退出 1）。原厂 JAR 和个人车辆配置不纳入 Git 历史。本次未改动自备固件内容，所有运行副本的写盘均位于独立输出目录。

另修正了非原车编码模式的车型资源参数传递：原分支在 chroot 内读取外层不存在的文件，现先复制到客体 RAM 的 `/tmp` 并从该路径读取。相同 21 位模拟输入的实际 shell 分支测试结果为：BASELINE 使用旧 16 位回退、MODIFIED 使用 21 位资源键、ROLLBACK 恢复旧回退；三次退出均为 0。没有把模拟资源选择称为原车编码或身份。

8704 资源须由使用者自行准备。本仓库不提供其下载链接；部署步骤和文件布局以根目录 README 为准。
